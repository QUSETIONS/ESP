# GoTim_ink V1.0 发布检查与续航逻辑汇报

日期：2026-07-06

## 结论

当前版本适合作为 `GoTim_ink V1.0 demo candidate`，不建议直接定义为最终量产 `V1.0`。

原因有三点：

1. 固件已经恢复“极趣实验室/便利贴原始功能”为默认首页，会议助手作为实验室额外功能并存。
2. 会议助手的议程、资料二维码、AI 要点、个人提醒、长文本滚动和服务地址配置已经具备 demo 基础。
3. 续航策略仍是“开机后常亮运行”，尚未对标会议纪要里提到的 RTC/低功耗定时唤醒；最新烧录后还需要再完成一次真机联网拉取数据验收。

当前目录不是 Git 仓库，没有 `.git`，因此这里不能实际创建 `GoTim_ink V1.0` commit/tag。拿到真实 Git 仓库后再执行发布标签。

## 当前开机与运行逻辑

### 开机流程

1. `CustomBoard` 构造时初始化电源、I2C、RTC、NFC、充电检测、墨水屏和按键。
2. `InitializePower()` 立即打开 VBAT、电源音频和 EPD 电源，并等待 VBAT 电源脚就绪。
3. `Application::Initialize()` 启动音频服务，刷新状态栏，进入 idle 状态。
4. 默认进入 `StickyNote` 首页，即原便利贴/极趣实验室那套原始功能入口。
5. 随后启动网络：如果没有保存 Wi-Fi，就进入配网页面；如果已有 Wi-Fi，就以 station 模式连接。

对应代码：

- `main/application.cc`: `Initialize()` 里执行 `board.EnterNormalMode()` 和 `board.StartNetwork()`。
- `main/boards/zectrix-s3-epaper-4.2/zectrix-s3-epaper-4.2.cc`: `InitializePower()` 打开 VBAT、Audio、EPD。

### 会议助手进入方式

1. 默认首页保持原便利贴功能。
2. 会议助手放在实验室额外功能里。
3. 按键逻辑保留了返回关系：在会议助手里长按确认键返回实验室功能；在实验室功能里长按确认键返回原便利贴首页。
4. 工厂测试模式在正常使用路径里不进入，`IsFactoryTestMode()` 固定返回 `false`。

### 联网与会议数据

1. 有 Wi-Fi 配置时自动连接。
2. Wi-Fi 连接成功后启动一次会议数据拉取任务。
3. 会议接口地址现在支持在配网页面配置，保存到 NVS；未配置时回退到编译期默认地址。
4. 拉取失败会重试 3 次，每次间隔 3 秒，HTTP 超时 10 秒。

### 当前续航逻辑

当前固件不是低功耗逻辑，而是常规在线运行逻辑：

1. CPU 主任务常驻，`Application::Run()` 无限等待。
2. `Application::CanEnterSleepMode()` 固定返回 `false`，所以 SleepManager 不能进入睡眠。
3. `SetPowerSaveLevel()` 当前为空实现，没有真正切换 Wi-Fi/系统功耗档位。
4. `lvgl_display::SetPowerSaveMode()` 当前也是空实现。
5. EPD、Audio、VBAT 在开机阶段打开后，正常路径里没有主动关闭。
6. 充电/满电 LED、ADC 电池电量读取是可用的，但这只是状态显示，不是省电策略。

也就是说，目前的 demo 固件可以稳定展示功能，但不能按低功耗产品形态汇报续航。

## 对标之前固件/需求纪要

### 已对齐

1. 保留原始便利贴首页和基础体验。
2. 会议助手作为实验室扩展功能并存，而不是替换原功能。
3. 支持多页会议信息：议程、资料二维码、AI 要点、个人提醒。
4. 支持物理按键翻页和返回。
5. 支持通过 Wi-Fi 拉取后端会议 JSON。
6. 支持二维码展示，资料下载和互动入口可以通过 URL/二维码承载。
7. 工厂测试模式没有出现在普通用户路径里。

### 未完全对齐

1. 低功耗未完成：会议纪要里提到的 RTC/低功耗定时唤醒还没有落地。
2. 母机/集中管理未完成：目前是设备直连 Wi-Fi 后端，不是母机广播更新。
3. 微信小程序 BLE 未完成：当前配网和数据更新主要依赖 Wi-Fi/HTTP。
4. iPhone 单机 demo 未完成：现在仍依赖热点和后端服务；如果后端跑在电脑上，Jasper 不能只拿 iPhone 和设备出门。
5. 录音、说话人标签、ASR、会议总结链路还没有接入火山 API 或小程序端。

## V1.0 发版建议

建议把当前状态定义为：

`GoTim_ink V1.0 demo candidate`

发版前必须补做两项验收：

1. 真机联网验收：最新烧录固件需要在目标 iPhone 热点下成功连接，并拉取 `/meeting/current` 数据刷新会议助手。
2. 续航口径确认：如果只是 demo，可以明确写“常亮在线 demo 模式”；如果要对外讲续航，需要实现或至少设计低功耗策略。

## iPhone 单机 Demo 路线

目标：Jasper 只带一个墨水屏设备和一台 iPhone，就能给客户演示完整流程。

### 阶段 1：当前可演示形态

1. iPhone 开热点。
2. 设备连接 iPhone 热点。
3. 后端服务提供会议 JSON。
4. 墨水屏显示议程、资料二维码、AI 要点、个人提醒。

限制：如果后端跑在电脑上，仍然不是 iPhone 单机 demo。

### 阶段 2：微信小程序 + BLE

建议优先做微信小程序 BLE，不再依赖电脑后端：

1. 小程序扫描并绑定设备。
2. 小程序编辑/选择会议议程。
3. 小程序把会议 JSON 通过 BLE GATT 写入设备。
4. 设备本地保存并刷新墨水屏。
5. 二维码只负责展示下载链接、提问入口、资料入口，不让设备直接存大文件。

设备侧建议定义一个简单协议：

```json
{
  "meeting_id": "demo-001",
  "title": "会议标题",
  "agenda": [],
  "materials": [],
  "highlights": [],
  "reminders": []
}
```

### 阶段 3：录音、说话人标签、总结

建议把重计算放在 iPhone/云端，不放在墨水屏设备：

1. 小程序发起实时录音。
2. 音频上传到火山引擎等 ASR 服务。
3. 云端完成语音识别、说话人分离/标签、会议总结。
4. 小程序展示完整内容。
5. 小程序把摘要、当前议程、提醒、资料二维码同步给墨水屏。

这样设备只负责低功耗展示和按键翻页，复杂 AI 能力由手机/云端承担。

## 给张晨钰的汇报口径

目前固件开机后先上电 VBAT、音频和墨水屏，再进入原便利贴首页并启动网络；有 Wi-Fi 时自动联网，联网成功后拉取会议助手数据。会议助手没有替代原功能，而是放在实验室额外功能里，两个功能并存。

续航方面，当前版本还不是低功耗固件。虽然代码里有 RTC、电池 ADC、充电状态检测和 SleepManager 框架，但实际运行中 `CanEnterSleepMode()` 固定返回 false，EPD/Audio/VBAT 正常路径也不会关闭，所以现在应按“常亮在线 demo 模式”汇报，不能按低功耗产品模式汇报。

对标之前需求，会议议程、资料二维码、AI 要点、个人提醒、按键翻页、原首页保留这些 demo 核心项已经具备；还没完成的是 RTC 定时唤醒、BLE 小程序同步、iPhone 单机闭环、ASR/说话人标签/会议总结传输。建议当前先作为 GoTim_ink V1.0 demo candidate 验收，等真机联网和续航口径确认后，再在真实 Git 仓库打 `GoTim_ink_V1.0` 标签。
